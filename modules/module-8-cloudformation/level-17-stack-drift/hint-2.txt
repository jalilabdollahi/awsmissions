CloudFormation only knows what the template says; it does not watch the real resources. Changes made outside it are drift. Running update-stack with an unchanged template does nothing, because the template did not change, and manually reverting the resources would throw away the incident fix.

The correct direction here is reality to template: make template.json describe what is running (including the extra environment variable the engineer added, which is easy to miss), then update the stack so the stored template matches. After that the next deploy keeps the hotfix.
